# Research 评分恢复

`rejudge_research_dev.py` 仅在显式调用时运行，要求隔离的本地 PostgreSQL `*_test` 数据库以及预算参数。

每次调用在 `judge-checkpoint.sqlite3` 中先记录 STARTED；收到响应立即提交，再解析。完整案例、原始输入和账本另存为 JSON。续跑使用新的输出目录与 `--continue-from 原目录`，复制检查点，沿用冻结参数；成功响应直接复用，原目录不改。

如果检查点中调用处于 STARTED，续跑默认停止，不推断它未发送。确认权威账本已将该调用标为 FAILED 且所有尝试费用已结算后，可显式追加 `--retry-failed-invocation 调用ID`。旧记录转入 retired_calls，新的尝试使用新调用ID并受新预算控制。SUCCEEDED、未结算、跨用户或未知状态均拒绝重试。

响应截断和无效 JSON 已保存，因此不会静默重发；需要另建明确版本/配置的评测。没有检查点的旧实验无法恢复未保存的单份响应。

收到提供商响应到本地提交之间存在不可消除的进程崩溃窗口；此时保留 STARTED 并阻止重发，不宣称网络调用 exactly-once。

本地检查点含研究回答，不含凭据；应与实验目录按相同访问权限保存。完整真人评分仍需人工填写，代理诊断标签不会转换成真人标签。

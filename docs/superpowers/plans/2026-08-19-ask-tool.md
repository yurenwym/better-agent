# Conversation Ask Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a durable, structured `ask_user` interaction to the Conversation V2 flow so the model can pause for user choices/input and resume the same thread without exposing raw tool JSON.

**Architecture:** Treat `ask_user` as a special conversation control tool, not a normal side-effecting `ToolRegistry` tool. A validated tool call becomes a persisted `turn_asks` record and `AWAITING_INPUT` Turn; answering creates an idempotent child Turn with `parent_turn_id`, a readable user message, and a queued job. The existing single-process worker, Thread SSE, event sequencing, and Markdown message flow remain the source of truth.

**Tech Stack:** Python 3.11, FastAPI, SQLite WAL, pytest/pytest-asyncio, React 18, TypeScript, Vitest, Testing Library, existing fetch/SSE helpers.

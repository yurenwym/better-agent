# 模型上下文预算与压缩：分期开发实施方案

日期：2026-09-18  
状态：待实施。本文是开发任务说明，不代表业务代码、迁移、校准或测试已经完成。  
优先模型：项目当前配置的 DeepSeek 模型；具体端点、模型版本和容量以实施时证据为准。

## 1. 实施决策

**先修复预算主链，再处理压缩体验，最后按收益选择复杂机制。**

首版 R1 必须解决：固定 12,000 热窗口不随模型变化、历史提前裁剪、完整请求预算口径不统一，以及已归档来源的摘要在最终打包中被优先丢弃。复用当前 Episode、归档任务、租约和事务，不新增 Facts、manifest、恢复补读三个状态机。

**R1 的目标形态（验收基线）**：压缩后返回给 LLM 的是「**摘要 + 最近几轮对话**」——摘要确定性进入本轮消息且不被优先丢弃，最近若干轮完整 Turn 原文按轮数下限保留。达不到这个形态，R1 就不算完成；只改善保留量、归档次数和延迟不算。

| 发布阶段 | 本期内容 | 本期不做 |
|---|---|---|
| R1：预算正确性 | A级准入、完整请求计数、动态历史预算、移除固定热窗口、摘要确定性注入与轮数下限、调用前最终校验 | 自适应 G、通用事实抽取、新 manifest、缺失历史后的自动恢复 |
| R2：容量与等待体验 | 工具结果投影、N/R 双约束、已有 Worker 的静态提前归档、限流与等待 UI | 不依赖B级估算或新增 Facts 状态机 |
| R3：可选效率优化 | B级计数校准；有足够样本后评估自适应调度 | 不反向阻塞 R1/R2；B级计数不与 G 绑定发布 |
| R4：单独立项 | Facts 生命周期、候选 manifest、恢复补读和程序证据门控 | 没有明确业务需求和验收资源时不实施 |

R1 交付分三个提交组：M1 预算契约、M2 调用链修复、M3 验收与灰度。各组内的具体任务见下文；测试随任务完成，不集中拖到最后。

## 3. 统一预算契约

### 3.1 Profile 字段

| 字段 | 含义及首版处理 |
|---|---|
| `context_window`（C） | 模型真实最大总窗口；未知必须明确表示未知 |
| `admitted_context_limit`（A） | 有证据的准入工作容量，必须参与计算 |
| `soft_context_limit` | 产品期望总工作窗口，不等于模型真实能力 |
| `max_output_tokens`（O） | 输出预留；本次请求允许输出不得超过它 |
| `counter_id/version` | 计数实现和不可变版本 |
| `counter_evidence_version` | 字节/协议预算依据及适用域 |
| `capacity_evidence` | 官方、代理配置或实测准入范围的来源和日期 |
| `validation_tier` | R1 仅启用 A；B 以后实现 |

```text
S = min(soft_context_limit, admitted_context_limit=A, context_window=C 若已知)
H = S - O
发送条件：完整输入预算计数 U <= H
```

**A 永远不能省略。** A 未通过验证时，不允许退回 min(soft,C) 绕过门禁。所有构建、归档和 Gateway 使用一个预算入口，不复制公式。

固定示例仅用于测试，K=1024：

| C | A | soft | O | S | H |
|---:|---:|---:|---:|---:|---:|
| 128K | 64K | 128K | 8K | 64K | 56K |
| 未知 | 32K | 128K | 8K | 32K | 24K |
| 200K | 128K | 128K | 8K | 128K | 120K |

这些不是 DeepSeek 的规格或默认配置。未核实前不自动扩大现有生产容量。

### 3.2 A级计数具体实现

复用 `Utf8UpperBoundTokenCounter.count_payload(messages, tools)` 的规范化 JSON 口径：

```text
byte_bound = len(canonical_json(messages, tools).encode("utf-8"))
protocol_bound = b0 + bm * message_count + bt * tool_definition_count
                 + bc * tool_call_count + br * tool_result_count
U_A = byte_bound + protocol_bound
```

要求：

- 字节是保守 Token 预算，不是真实 Token。验证文本 tokenizer 的字节上界假设，以及消息/工具模板的覆盖范围。
- b0/bm/bt/bc/br 是适配器的非负包装预算，必须有记录；不能默认 0 或任意写 4096。额外协议项需单独计入。
- 若只能通过完整请求样本建立经验保守边界，应明确标为经验验证，限定类型、长度、消息/工具数量，不声称是理论上界。
- 连经验保守证据都没有的适配器不能通过A级准入；不要求所有模型一起通过。
- R1 只覆盖已验证文本和工具 JSON。图片、音频或未支持协议不能套用该公式视为已计数。
- 已包含的开销不得再次从 H 扣除。原 safety_margin 不得与新协议预算无说明叠加。

B级以后才采用 `U_B=ceil(alpha*E+beta)`。R1 不依赖 alpha/beta，也不以 alpha=1、beta=0 假装完成校准。

### 3.3 两级准入与证据不足的处理

| 等级 | 通过标准 | 放行范围 |
|---|---|---|
| A | 端点/模型身份、单位一致的可用容量、计数证据、输出口径、代表性请求可发送 | R1；R2 另行验收 |
| B | A 加独立验证集误差、适用域、时延和增长样本 | R3 的对应优化 |

没有官方精确最大值不等于 A 无法通过，可以使用有证据的较小准入容量。仓库默认值本身不算证据。无法验证某 Profile 时，只暂停它的新策略发布；配置接口、离线测试和其他 Profile 可继续。

必要时采用有预算的容量探测：固定端点、输入格式和输出预留，递增输入找到成功点，再针对明确上下文拒绝做二分。初始总请求上限候选 16 次，同时限制费用与时间；不把 429、超时或请求体大小限制当作 Token 上限。只记录经验准入范围，不声称找到模型真实最大窗口。未找到拒绝点也可保留经过验证的较小成功范围。

探测候选可从成功下界降额后验证，例如先取 80%；这是实验降额参数，不替代计数验证。本次任务只制定方案，不执行模型探测。

### M2-01：先构建完整请求，再判断缩减

依赖：M1-03。

修改位置：`conversation.py`、`live_model.py`、`context.py`、`memory_v2.py`、`transcript.py`。

操作：

- [ ] 将实际固定路由 Profile 解析到构建阶段；调用构建函数不产生外部副作用。
- [ ] 构建 System、当前输入、任务状态、计划发送的 Memory/Episode、完整可用历史、Tool Call/Result 和 Schema。
- [ ] 移除 `_history()` 在完整计数前按 12,000 裁剪的路径；大历史可分页读取，但不能因查询条数限制悄悄丢失来源。
- [ ] 先去除重复及低相关可选检索内容，再判断剩余请求是否超 H；不要为了可选 RAG 提前压缩本来可容纳的原文。
- [ ] 历史来源仍按完整 Turn 和工具配对分组；canonical JSON 计数仅用于内部规划，不能作为最终 Prompt 计数。
- [ ] 如需选择待归档前缀，以完整候选重新计数判断收益；不能只计算 H 减去“正文长度”而忽略消息/工具包装。
- [ ] **定义 R1 的归档停止规则与静态余量。** R1 不引入自适应 G，但只规定“不超 H 就发送”会让停在 H 附近的会话每轮归档一次。归档后重建的完整计数目标为 `compact_target = ceil(compact_ratio × H)`，`compact_ratio` 初始候选 0.7（即保留约 30% 余量），由 Profile/版本化策略提供，选择器内不得留绝对字节常量；只压“达到该目标所需的最小完整前缀”，不额外多压。
- [ ] 若达到 `compact_target` 必须牺牲硬保护内容，则放弃本次归档，走明确失败/可重试，不把硬保护内容当作可压缩前缀。
- [ ] **给 `pack_recent` 增加轮数下限 `min_turns`（初始候选 5）。** 现状 `pack_recent`（`transcript.py:236-245`）只按字节从最新往前收、装不下就 `break`，保留几轮完全由轮大小决定：正常中文对话（每轮约 1–2KB）约 6–8 轮，但某一轮带大工具结果时会掉到 0–1 轮。改为：**先无条件纳入最近 `min_turns` 个完整 Turn，再用剩余预算继续往前补**；只有当单个 Turn 自身就超过可用预算时才允许少于 `min_turns`，且必须记录该退化事件。轮数下限与 `compact_target` 的余量目标同时生效；两者冲突时以硬上限 H 为准，并在预算记录中标注是哪一侧触发了退化。
- [ ] 保护当前用户输入、System/权限和未闭合工具依赖。R1 不实现 R2 的完整 N/R 近期保护策略（`R` 预算上限、从最老近期轮次释放软保护），但**必须提供上面的轮数下限保证**；不得以"尚未实现 N/R"为由随意减少保留轮数。

交付：可重建的完整候选请求和分项预算记录。

验收：历史超过 12,000、完整 U_A<=H 时不归档、不先裁剪；短历史加大 Schema 超限时能正确发现；确需归档时重建计数落在“可达最小值至 `compact_target`”区间内，且同一输入停在 H 附近连续多轮不产生每轮归档；**保留轮数不少于 `min_turns`，仅在单个 Turn 自身超预算时允许退化并留记录**。

### M2-02：归档预算解耦和既有事务复用

- [ ] **已归档来源对应的 Episode 必须能在最终打包中存活。** 现状 `conversation.py:1588` 给 memory-context 设 `_context_priority=20`，而原始历史不带该键、在 `token_budget.py:211` 取默认 50；`pack_messages_newest` 按优先级从低到高丢弃，因此预算一紧就**先丢已压缩的 Episode、后丢原文**。注入成功不等于进入最终 Payload，M3 的“摘要进入本轮”用例会假通过。R1 必须把已归档来源对应的 Episode 优先级提到不低于原文历史（或标记 `_context_required=True`），并在完整计数超限时断言 Episode 与它覆盖的原文不会同时消失。
- [ ] 摘要输出侧一并校正：`MAX_SUMMARY_OUTPUT_TOKENS=1_600`（`memory_archive.py:16`）计量单位是**字节**，且字段名与 `source_message_ids` 都计入该预算；`_merge_chunk_summaries`（`memory_archive.py:437`）按 `("synopsis","decisions","outcomes","open_loops","topics")` 顺序逐字段抽干，多 chunk 长归档下 decisions/outcomes 会被饿死。R1 至少改为跨 chunk 交错抽取，或给 decisions/outcomes 预留配额。
- [ ] 摘要未提交时不丢弃原文；已提交摘要仍装不下时重建并校验，在现有任务期限和重试预算内处理，不能无限循环。
- [ ] 若失败、无收益或没有可归档前缀，沿用明确失败/可重试处理，不将缺失历史后的开放回答当作恢复成功。

交付：基于完整请求触发的归档接入、独立摘要预算、来源替换回归测试。

验收：并发会话不串预算；新 Episode 与其覆盖历史不会同时遗漏（含预算紧张时 Episode 不被优先丢弃）；租约失效不能提交；错误不提前推进覆盖。R1 仍可能等待现有归档完成，必须如实记录时延。

### M2-03：所有调用的最后一道校验

依赖：M2-01；归档相关路径依赖 M2-02。

修改位置：`model_gateway.py`、`model_control.py`、`live_model.py` 和 M1-01 列出的各入口。

操作：

- [ ] 对话首调、工具续调、修复调用、规划/执行/研究和摘要调用都检查实际 Payload。
- [ ] 摘要调用只用自身预算，不递归触发会话归档。
- [ ] 计数完成后若增加消息、工具或输出上限，必须重新计数，禁止复用旧结果。
- [ ] fallback 按实际 Profile 重算 H/U_A；能安全重建则重建，不能则明确跳过该 fallback，不静默裁剪硬保护。
- [ ] 不重放已执行工具，不将内部打包提示发送给供应商。
- [ ] 服务端容量拒绝最多进行一次有实质缩减/保守修正的重建重试；无变化不重发，记录当前证据失效。

交付：调用清单逐项勾选及 Gateway/fallback 测试。

验收：所有实际请求都经过统一预算校验；不同模型窗口不复用预算；请求修复新增内容也受限制。

### M3-01：回归、收益评估与灰度

依赖：M1/M2 对应功能完成；单元测试已随提交执行。

操作：

- [ ] 执行下节验收矩阵、数据库迁移及必要集成测试。
- [ ] 比较同一输入集的新旧原文保留量、提前归档次数、失败率、首 Token/归档等待和费用。
- [ ] **质量回放（R1 硬性验收）**：用一组已知答案任务，测约束遵守、最新纠正值、已确认参数、工具结果、失败尝试与未解问题；比较未压缩参考、R1 前后以及不同 `min_turns`。只测保留量/归档次数/延迟/费用**不能**证明"比现在好"——机制指标改善而质量下降必须判为不通过。
- [ ] 报告A级保守计数效率与真实利用率，不用预算填充率冒充真实利用率。
- [ ] 一个发布开关，只对通过A级证据的 Profile 小范围启用；运行中固定 Profile 不原地修改。
- [ ] 关闭新策略可回退，原始消息和 Episode 不删除；兼容旧 Thread 与旧归档 Job。
- [ ] 交付完成/未完成清单，明确同步等待、超大当前 Turn 和自动恢复仍属于后续任务。

交付：R1 测试报告、收益报告、配置版本与回退操作说明。

发布门槛：预算与来源正确性用例必须全部通过；**「摘要 + 最近几轮对话」的目标形态可复现（摘要确定性注入、轮数不少于 `min_turns`）**；**质量回放不劣于基线（容差在基线阶段登记）**；延迟、成本和收益的数值门槛在基线阶段登记，不能测完再降低标准。收益不足或出现新回归，不扩大灰度。

## 5. R1 必测矩阵与量化口径

| 场景 | 必须观察到的结果 |
|---|---|
| C=128K、A=64K、soft=128K | S=64K，所有路径一致 |
| C 未知、A 已验证 | 可以按 A 运行；不把 C 当作无穷大或 0 |
| A 缺失/证据失效 | 新策略拒绝准入，不绕过 |
| 相同历史、32K/64K/较大准入容量 | 预算随 Profile 变化，非固定 12,000 |
| 历史>12,000且完整请求可容纳 | 不提前裁剪或归档 |
| 大 Schema/Memory/当前输入 | 完整计数覆盖，超限不能发出 |
| 中文、英文、代码、工具 JSON | 计数稳定，模式/适用域清晰 |
| 两个不同 Profile 的会话并发归档 | 不共享临时 keep_tokens 或摘要预算 |
| 归档成功但检索不相关 | 新覆盖的原文有对应摘要进入本轮，不因检索缺失形成缺口 |
| 完整计数超限且已归档 | 已归档来源对应的 Episode 不被优先丢弃，不与它覆盖的原文同时消失 |
| 同一会话连续多轮停在 H 附近 | 不出现每轮归档；归档频率与重建计数有观测记录 |
| 普通多轮对话（每轮约 1–2KB） | 保留轮数不少于 `min_turns`，不随字节波动掉到 1–2 轮 |
| 某一轮含大工具结果 | 允许少于 `min_turns`，但必须记录退化事件；不出现 0 轮且不静默丢来源 |
| 压缩后质量回放（已知答案任务） | 需引用历史细节的问题（最新纠正值、已确认参数、工具结果、未解问题）答对率不劣于基线 |
| 摘要失败、租约过期、事务中断 | 不发生未提交摘要却推进覆盖 |
| 修复调用和较小 fallback | 重新校验，无硬保护静默丢失、无工具重放 |
| SQLite/PostgreSQL 与旧配置 | 迁移和兼容可验证，原始来源保留 |

量化定义：

```text
q = actual_prompt_tokens / U_A       # 计数保守效率
f = U_A / H                         # 预算填充率
eta = actual_prompt_tokens / H      # 真实利用率
eta = q * f
```

若特定样本字节数约为真实 Token 的 2–5 倍，包装较小且填满预算，eta 约为 20%–50%。这只是条件示例，不能写成 DeepSeek 的预期区间。按输入类型报告实际观测区间和样本量；usage 缺失则标未知。A级预期收益是解除不合理的固定窗口，而不是接近模型真实容量上限。

优先扩展现有测试：

```text

backend/tests/test_transcript.py
backend/tests/test_model_gateway.py
backend/tests/test_routed_model_gateway.py
backend/tests/test_memory_archive.py
backend/tests/test_memory_conversation_flow.py
backend/tests/test_memory_v2.py
backend/tests/test_model_control.py
backend/tests/test_model_admin_api.py

```

从 backend 运行受影响测试；例如：


仅使用测试数据库。报告区分离线 mock、数据库集成和真实模型调用，不从 mock 推断实际费用/时延。

## 6. R2：四项任务，独立改善容量与等待

依赖 R1；不要求 R3/R4 完成。

### R2-01：大型工具结果投影

- [ ] 审计工具结果和 Artifact 存储，补齐稳定 event_id/artifact_id 与作用域。
- [ ] 原文先持久化，再将上下文改为状态、必需字段、有限片段和引用。
- [ ] 每种工具定义不得省略的参数/错误码/结果字段，不以未经验证的 LLM 简述替代权威结果。
- [ ] 读取详情支持范围/分页和再次预算校验，防止整份读回撑爆窗口。
- [ ] 测持久化失败、无旧 Artifact、跨作用域读取和工具调用/结果配对。

验收：大日志不重复长期占窗，原文可恢复，不改变已执行结果的事实。

### R2-02：近期 N/R 双约束

初始实验参数：

```text
N = 5
R = min(16384, floor(0.25 * H), max(0, T - P))
```

P 是硬保护、必需摘要和包装预算；T 为本期静态压缩目标，由 R2-03 定义为 `T = B - D`。R2-03 未启用时 R 只取 `min(16384, floor(0.25 * H))`，不得让 T 处于未定义状态。数值放入版本化策略，不硬编码在选择器。

- [ ] 最近完整 Turn 按连续后缀选择，轮次<=N且原文预算<=R。
- [ ] 先投影大工具结果；仍超 R 时从最老近期轮次释放软保护，进入可压缩前缀。
- [ ] 当前指令和未闭合依赖硬保护；当前长 Loop 的已完成过程可投影，不保护整个无限增长 Turn。
- [ ] 最新大轮次不得被跳过而回填更旧小轮次；全量装得下时不因 R 裁掉原文。
- [ ] 固定 R 回放 N=3/5/8，测指代、纠正、工具链、频率和时延，选满足门槛的最小 N。5 只是中间实验起点，无理论最优声明。

验收：近 5 轮占 90K 不因“5轮硬保护”固有卡死；R 不是另一个提前截断热窗口。

### R2-03：复用现有 Worker 的静态提前归档

- [ ] 根据稳定快照和固定有效 Profile 评估静态触发线，明确每个 Job 的来源范围和预算版本。
- [ ] 初始 G=30%H、D=20%H 仅作为回放候选，B=H-G、T=B-D；通过延迟/质量验收后采用，不宣称预测P95。
- [ ] 同快照 Job 幂等；没有新增可压缩来源、没有净收益时不重复生成。
- [ ] 设置后台并发/费用/速率上限，前台优先，不持有整段回答生成锁。
- [ ] 复用现有事务/覆盖游标；调用构建时读取一致的已提交归档状态。后台完成不能改变已发出的 Prompt。
- [ ] 装得下时不等待后台；不建立新 manifest。确实无法安全缩减时维持明确可恢复等待，而非缺历史继续回答。

验收：后台摘要延迟 60 秒时，可容纳请求照常发送；无队列风暴、跨会话预算串用或覆盖缺口。

### R2-04：等待状态、取消与时延验收

- [ ] 显示真实整理状态，区分状态提示和模型首 Token，不把提示计作首字改善。
- [ ] 设置有限前台等待，初始候选 2 秒；超时保存当前输入/任务状态并提示稍后恢复，不伪装自动恢复成功。
- [ ] 取消等待不取消已完成外部操作，Thread 保持可接收输入；重新执行必须校验旧任务状态。
- [ ] 测后台开/关的P50/P95、本地计数耗时、等待率、取消与重启；本地新增耗时P95候选目标200ms，状态提示候选目标1秒内。

验收：时限有边界、等待可取消、任务不因一次超时永久不可用。相关原任务可能仍需等待摘要，不能承诺所有后续消息立即回答。

## 7. R3：可选效率优化，两项独立任务

### R3-01：B级计数校准

- [ ] 按模型/端点/协议固定样本范围，划分校准集与独立验证集。
- [ ] 拟合非负低估包络 U_B=ceil(alpha*E+beta)，报告P95/P99、最大观测低估、越界率、样本量；不足以估计则明确标记。
- [ ] 验证超长度/类型/版本适用域时切A级，服务端拒绝后最多一次有效重建，停止原请求无限重发。
- [ ] 将计数校准版本纳入 Profile，测相对A级的真实利用率、费用和失败率。

验收：经验包络不冒充数学上界；没有正收益不启用；B级失败不影响A级交付。

### R3-02：G/T 有限迭代

依赖 R2 的吞吐/增长数据；不是 R3-01 发布的前置。

- [ ] 固定计数版本、批次输入/输出、并发、Job 截止时间和某个 D 候选，再从通过回放的静态 G 开始。
- [ ] 测从入队到可用归档完成的全过程，包括排队、分块、重试与提交；映射增长轨迹得到 G_required。
- [ ] 使用 G_next=max(G_current,G_required)；每个 D 最多4轮，连续两轮变化/H<=5%且质量、时限、增长覆盖验证通过才接受。
- [ ] 参数不合法、样本不足、无净收益、调用预算耗尽或不收敛立即停止，维持静态策略。
- [ ] 比较多个D候选的质量、重复压缩、延迟和成本，选择数据支持的配置，不能固定100K→50K。

验收：有明确收敛/退出报告，无无限探测或以无界G求稳定。

## 8. R4：需单独立项的三个功能与一个交互检查

这些任务不是首版执行要求；实施前确认真实需求，否则保持未实现。

### R4-01：最小 Facts 生命周期

- [ ] 先列字段归属：Task State/权限仍由现有服务维护，Facts 只存补充参数/约束，Summary 存过程与引用。
- [ ] 实现 propose/confirm/supersede/invalidate、来源/写入者/作用域校验及版本冲突控制。
- [ ] 模型只能提出 proposed；确认来自明确用户确认或受限业务验证器，引用存在不等于语义确认。
- [ ] 明确字段纠正替代旧值；歧义纠正记录冲突，仅阻止依赖该值的操作，不覆盖任意旧事实。
- [ ] 更新使相关摘要/缓存失效，测试助手建议、伪造来源、工具失败、并发纠正和跨任务写入。

验收：Facts 不成为第二份 Task State；语义提取不控制权限或自动确认根因。

### R4-02：确有需要时引入候选 manifest

- [ ] 继续复用 Episode 与一个 Worker，候选仅保存，调用边界验证来源/事实/状态版本后CAS采用。
- [ ] 只有一个活动覆盖权威；迁移旧游标后禁止双写两个独立进度。
- [ ] 摘要按实体引用渲染权威值，Episode 按ID/lineage/来源范围去重，不新增模糊去重服务。
- [ ] 合并优先原文，旧摘要作提示；删除/失效来源不能由缓存复活。

验收：无第二套摘要生成器，过期候选不能采用，已有Thread和旧Job可迁移/兼容。

### R4-03：恢复补读与程序证据门控

- [ ] 由服务端 evaluate_source_gate(action_contract, snapshot) 返回ALLOW/NEED_SOURCE/UNDETERMINED，替换泛化“模型认为证据充分”。
- [ ] action_contract 由代码登记；检查参数、权限、scope、版本、确切来源和冲突，模型不能自建契约或删required_sources。
- [ ] 结构化操作只准入该操作；精确字段读取用受限结果；自由问答有历史缺口时默认UNDETERMINED，不靠模型自报独立性放行。
- [ ] 用户明确另起任务可创建新作用域，原任务仍暂停；不能把新任务当作原历史已修复。
- [ ] 恢复视图先校验能装下，再分配读取工作区。候选上限：每个epoch最多2次、单次2K、总时限2秒、累计min(8K,10%H)。
- [ ] 补读返回后在上下文外持久化，按范围片段替换工作区并重算；超限不注入、无进展停止，次数持久化，重试不得重置。
- [ ] 信息不足转可恢复等待，操作前提未满足不执行副作用。引用有效不证明任意自然语言结论正确。

验收：正文、状态机、伪代码与实际代码一致；没有补读→超限→再次补读的无界循环。

### R4-04：机制交互评审后再验收

对E=误差包络、Y=迟滞、C=候选CAS、R=恢复补读、F=Facts逐项检查：

| 组合 | 必查场景 |
|---|---|
| E×Y | 计数转保守使阈值变化，能紧急处理但不入队风暴 |
| E×C | 采用前计数模式改变，不能只凭CAS成功放行超限候选 |
| E×R | 补读中余量变小，拒绝超限注入且不重置次数 |
| E×F | 纠正增加保护量，重算R并保留当前事实 |
| Y×C | 重复触发/乱序完成，只有合法候选提交 |
| Y×R | 补读重放不被当作新增来源反复压缩 |
| Y×F | 冷却不能压住用户纠正后的失效 |
| C×R | 补读时版本切换/删除，来源重验且无重复注入 |
| C×F | CAS前用户纠正，提交事务检查事实依赖 |
| R×F | 读到旧值不能覆盖当前confirmed值 |

另做E×C×R、C×R×F、E×Y×F三机制轨迹和关键事务中断恢复。采用可控时钟/barrier/假Worker安排顺序，不只靠随机sleep。每个发现必须映射到测试和停止条件。

验收：超预算发送、旧事实采用、无限循环、重复副作用类未解决缺陷为0。R1/R2/R3只评审自身启用的机制，不等待全部R4功能。

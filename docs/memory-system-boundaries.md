# 记忆系统本版边界与运行规则

## 摘要与长期记忆

摘要只是较早对话的压缩档案，不会自动成为永久记忆。Turn 完成后，数据库触发器写入通知；后台轮询 Worker 创建任务，重新读取同一 Thread 的完整对话轮次，调用大语言模型生成严格 JSON，校验通过后，在同一事务中保存 Episode 并推进覆盖游标。下一次回答前，系统还会同步处理当前回答所依赖的待归档历史；只有摘要已经提交，旧原文才会退出模型上下文。

长期记忆只有两条入口：用户明确要求“请记住”并保存，或 Agent 反思先创建待审批的 `MemoryProposal`，用户接受后才创建 `MemoryEntry`。模型的置信度只是参考信息，不能绕过用户审批。

## 承接摘要（确定性注入）

归档提交时，`memory_archive_jobs` 的完成事务会同时保存 Episode 并推进 `conversation_archive_state.archived_through_seq`。这个已提交游标就是覆盖事实源：

```text
承接摘要：覆盖到 A 的已提交 Episode，按来源区间顺序全部渲染（必带）
近期原文：A 之后、Q 之前的完整历史 Turn（必带原子组）
当前输入：当前用户消息，只追加一次
辅助资料：长期记忆等，按相关度选择（可选，使用剩余预算）
```

选择承接摘要不读取问题关键词、embedding 分数、最近 K 条限制或 `episode_token_budget=1000`；只要归档已提交且预算可容纳，无论下一问是否相关都必须进入最终请求。游标 A 落在 Turn 中间、Episode 重叠/缺口、承接正文过大而无法容纳时，返回可区分的明确错误（如 `archive_coverage_missing`、`continuation_context_overflow`），不静默回退为“只看当前问题”，也不机械截断摘要正文。

默认保护最近 5 个完整历史 Turn（有模型配置时用 `history_min_turns`）。前台归档使用当前 Profile 的目标与 N，不再回退到固定的 12,000 保留窗口，因此新归档不会吞掉受保护的最近轮次。Pin 会成套固定 A/Q、Episode id/version/范围、承接正文、渲染版本与预算标识；编辑或删除摘要会使旧 pin 失效，发送前与生成中的撤销检查覆盖必带摘要。原始对话仍保存在数据库中。

## 摘要提示词

摘要模型被要求只返回固定字段：`synopsis`、`topics`、`decisions`、`outcomes`、`open_loops`、`sensitivity`。每个列表项必须包含正文和来源消息编号，来源编号必须来自本批次对话；摘要要使用“用户表示”“助手建议”“双方决定”等归因表达，不能把一次性陈述改写成永久事实。系统还会检查未知字段、空摘要、来源越界、敏感信息和总 Token 超限。

## 上下文与 Token

`12000` 是近期历史原文的保留预算，不是整个模型请求的总上限。最终请求还要容纳系统提示、工具说明、目标、计划、长期记忆、承接摘要、当前问题和输出预留。完整 Turn、工具调用及其结果、承接摘要、长期记忆条目都是原子块，只能整体加入或整体丢弃。

必带集合（硬性系统规则、必要目标状态、承接摘要、受保护近期原文、当前输入）先计入预算，可选资料（长期记忆等）只使用剩余预算。必需内容本身超限时返回明确容量错误，而不是在最终打包时静默去掉摘要或某几轮。

摘要输入过大时按来源分块，每块仍受 Token 上限和来源校验；JSON 非法或来源发生变化时，任务会重试或按新内容重建。若最终进入可追踪的死信状态，系统不偷偷截断原文、不推进覆盖游标，并在无法构造完整上下文时明确停止回答。原始消息仍保存在数据库中。

## 多用户与旧接口

新记忆接口按用户隔离。当前本地部署用 `x-owner-id` 作为临时身份；正式生产必须由认证中间件提供该身份，不能信任客户端自行伪造。Markdown 投影位于 `memory/users/<用户哈希>/`，不会共用 `USER.md`、`MEMORY.md` 或项目文件。

新版存储启用后，旧 `/api/memories` 写接口返回 `410 Gone`，避免旧候选表产生无法被新版上下文读取的“幽灵记忆”。

写接口使用幂等键防止网络重试产生重复数据。只要首次结果没有被后续操作改变，重试会返回等价结果；若记忆或摘要后来已编辑、归档或删除，则返回“旧结果已被取代”的冲突，要求客户端刷新。审计只保存结果版本或状态，不复制正文，确保删除后不会为了重放旧响应而残留内容。

## 本版不扩展的内容

本版不新增向量检索、新记忆类型、RocketMQ 或 Episode 自动升级长期记忆能力；目标是把摘要、上下文、审批、隔离、幂等、版本和删除链路做成可验证的一致行为。

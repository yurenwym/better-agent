# 记忆系统本版边界与运行规则

## 摘要与长期记忆

摘要只是较早对话的压缩档案，不会自动成为永久记忆。Turn 完成后，数据库触发器写入通知；后台轮询 Worker 创建任务，重新读取同一 Thread 的完整对话轮次，调用大语言模型生成严格 JSON，校验通过后，在同一事务中保存 Episode 并推进覆盖游标。

长期记忆只有两条入口：用户明确要求“请记住”并保存，或 Agent 反思先创建待审批的 `MemoryProposal`，用户接受后才创建 `MemoryEntry`。模型的置信度只是参考信息，不能绕过用户审批。

## 摘要提示词

摘要模型被要求只返回固定字段：`synopsis`、`topics`、`decisions`、`outcomes`、`open_loops`、`sensitivity`。每个列表项必须包含正文和来源消息编号，来源编号必须来自本批次对话；摘要要使用“用户表示”“助手建议”“双方决定”等归因表达，不能把一次性陈述改写成永久事实。系统还会检查未知字段、空摘要、来源越界、敏感信息和总 Token 超限。

## 上下文与 Token

`12000` 是近期历史原文的保留预算，不是整个模型请求的总上限。最终请求还要容纳系统提示、工具说明、目标、计划、长期记忆、Episode、当前问题和输出预留。完整 Turn、工具调用及其结果、Episode、长期记忆条目都是原子块，只能整体加入或整体丢弃。

摘要输入过大、JSON 非法或来源发生变化时，任务进入可追踪的失败/死信状态，不偷偷截断原文，也不推进覆盖游标。原始消息仍保存在数据库中。

## 多用户与旧接口

新记忆接口按用户隔离。当前本地部署用 `x-owner-id` 作为临时身份；正式生产必须由认证中间件提供该身份，不能信任客户端自行伪造。Markdown 投影位于 `memory/users/<用户哈希>/`，不会共用 `USER.md`、`MEMORY.md` 或项目文件。

新版存储启用后，旧 `/api/memories` 写接口返回 `410 Gone`，避免旧候选表产生无法被新版上下文读取的“幽灵记忆”。

## 本版不扩展的内容

本版不新增向量检索、新记忆类型、RocketMQ 或 Episode 自动升级长期记忆能力；目标是把摘要、上下文、审批、隔离、幂等、版本和删除链路做成可验证的一致行为。

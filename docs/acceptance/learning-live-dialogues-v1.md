# V3 真实模型对话测评集 v1

日期：2026-09-22

这是一套人工编写的现实场景测试数据，不冒充真实用户历史。测试时的助手回复、JEV 分类、候选生成、基线/候选回放和 Judge 均调用已配置的真实模型。

## 范围与标准

- 10 组发现阶段对话：2 组 Memory、2 组 IGNORE、3 组 Skill、3 组 Behavior。
- 28 个独立回放用例：Skill 8 个相关任务 + 8 个无关任务；Behavior 8 个目标任务 + 4 个邻近任务。
- Memory 必须真实写入隔离 PostgreSQL；IGNORE 不产生候选。
- Skill 成功率不得低于基线，Judge 加权胜率至少 0.60，无关触发率最多 0.05。
- Behavior 目标指标必须严格改善，邻近任务不退化、安全回归为零。
- Shadow 不修改启用资产和 runtime channels；模型实际回复和所有失败保留。
- 本套验证学习链路，不替代 M5 的 60 例发布评测和生产 20/20 Canary。

## 结果解释与边界

- 对话通过真实模型和会话存储驱动，不经过完整 UI/router；长期记忆验证入库，不等于已验证后续会话召回。
- Skill 历史工具轨迹是场景素材；本轮回放不执行工具，因此不能据此声称工具调用效率提高。
- Behavior 的确定性指标检查证据分层标记、来源标记和禁用表述，另外记录真实 Judge 比较；它不是完整的因果推理正确率。
- 每类回放数量较少，只支持这套固定场景的学习验收结论。8 个无关任务零误触发，不代表线上误触发概率为零。
- 首轮是冻结数据上的初测。若根据失败修正产品提示再跑，后续结果属于同一测评集上的开发回归，不能称为未接触过的独立最终评测；发布前应另备未使用的测试集。
- 隔离数据库中的 Shadow 检查关注启用资产和发布通道不变。候选生成、评测记录、审计记录允许写入；不发布到开发库或生产库。

## 执行与产物

在 backend 下运行：

```powershell
python scripts/learning_dialogue_live_acceptance.py          # 仅检查规模，不调用模型
python scripts/learning_dialogue_live_acceptance.py --live   # 新建隔离 PG 库并执行真实模型验收
```

每轮生成独立目录 `evals/results/learning-dialogue-live-时间戳/`，包括冻结 plan、两份数据快照、逐调用输入输出与增量 report。默认最多 300 次网关调用、LLM 预算上限 10 美元；JEV 预算按用户要求排除。不会修改开发库或本机 .env。

失败不能通过改标签或降低门槛消除。修复产品缺陷后使用相同数据另开新一轮，并保留前轮记录。

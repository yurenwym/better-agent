## 结论

Docker 和网络访问恢复后，已完成冻结 24 题的 PostgreSQL＋真实 embedding＋DeepSeek A/B 评测。两组严格答案均为 24/24，查询改写未提高答案通过率，并在 q03 造成前五召回退化。当前证据不支持把每轮 LLM 查询改写默认上线。

这只是 22 条记忆的小型诊断集：每题实际注入 7—17 条，很多干扰记忆也进入上下文，模型仍能答对。应先扩大难负例／独立留出集，再分别验证融合排序、候选筛选、预算和按需改写，不能把本次 100% 当作生产准确率。

- embedding：SiliconFlow `Qwen/Qwen3-Embedding-4B`，1024 维，沿用 0.8 秒超时；70/70 成功，所有 query 的有效记忆向量覆盖率为 1.0。
- DeepSeek：官方 HTTPS 端点，请求与响应的 model 字段均为 `deepseek-flash`；没有额外把别名推断成不可变版本号。temperature=0，thinking disabled，每次最多 256 输出 token。
- Windows 用户设置中的 `EMBEDDING_API_KEY_ENV` 指向 `AGENT_FALLBACK_MODEL_API_KEY`，现有加载器拒绝这一变量名前缀。首次专用库 live01 因缺少被加载器接受的凭据而停止，未开始推理调用。
- 成功批次仅在评测子进程中将明确配置的同一凭据映射到 `MEMORY_EMBEDDING_API_KEY`；没有输出密钥，没有修改持久环境或生产加载器。此处意味着生产配置仍需单独核对，不能声称原配置已经无修改跑通。

# [ACCEPT-FULL-JOURNEY-20260908-001]七天PostgreSQL实验

> 本计划用于验收，后续完成状态与反馈为模拟，不代表真实学习成果。

- 安全边界：只操作独立测试库，不影响现有数据；不宣称回滚可消除序列或外部副作用。
- 前置条件：基础SQL能力，已有Docker环境。
- 每天固定预算：60分钟。

## 第1天（60分钟）：环境与基线

- 行动：启动独立 PostgreSQL Docker 容器，创建专用测试库与测试表，验证连接和基本读写。
- 可验证产物：测试库可用；`SELECT version();` 有正常输出；测试表可完成简单写入与查询。

## 第2天（60分钟）：B-tree等值范围

- 行动：在测试表整数列上创建 B-tree 索引，执行等值查询和范围查询。
- 可验证产物：记录等值与范围查询的实际 EXPLAIN 输出；若未使用索引，结合数据量、选择性和统计信息解释原因，不强求指定扫描类型。

## 第3天（60分钟）：Hash等值

- 行动：在测试表上创建 Hash 索引，对比等值查询与范围查询的执行计划。
- 可验证产物：隔离比较无索引、B-tree 和 Hash，记录实际执行计划；说明 Hash 仅支持简单等值，查询是否使用索引以实测为准。

## 第4天（60分钟）：EXPLAIN读计划

- 行动：对第2/3天典型查询执行 `EXPLAIN`，识别节点类型、估算成本、估算行数等关键字段。
- 可验证产物：一段约5句话的读计划笔记，说明如何判断 Index Scan 与 Seq Scan。

## 第5天（60分钟）：事务回滚边界

- 行动：在独立测试库中执行 `BEGIN` → 插入/更新 → `SELECT` 验证可见性 → `ROLLBACK`，并观察序列变化。
- 可验证产物：回滚后表行数恢复原值；记录“序列不会因回滚回退”的观测结论。

## 第6天（60分钟）：重复测量

- 行动：对同一查询执行 `EXPLAIN ANALYZE` 至少5次，记录每次实际执行时间。
- 可验证产物：一份包含5次耗时数据及波动范围的简短记录。

## 第7天（60分钟）：总结复现

- 行动：将前六天的关键命令和结果整理为简明复现清单，并重新运行 B-tree 与 Hash 两个代表性查询。
- 可验证产物：一份“七天实验复现清单” Markdown 文档，包含步骤、关键命令与实际输出摘要。

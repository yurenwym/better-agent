## 尚存问题：响应被拒绝时丢弃已知 usage（P2）

位置：`backend/app/model_control.py:1074`。

请求已成功返回后，如果资产在途撤销，RoutedModelGateway 的响应后检查会调用：

```python
self.control_store.finish_attempt(active, ordinal, "failed", "asset_revoked", None)
```

此时真实 response 已经存在，并携带 usage；传 None 导致 finish_attempt 把已知 token 使用量写成空值，usage_status 变成 UNAVAILABLE。配置成本结算时也无法基于实际 usage 结算，可能回落估算。该成本影响来自代码路径分析，本次未接真实计费服务。

独立复现使用真实 LearningAssetService、ModelControlStore 和 RoutedModelGateway，仅模型响应为桩：execute 中撤销当前 bundle，再返回 input=1/output=1 的完整 usage。实测：

```text
exception: LearningConflict
provider usage: input=1, output=1
attempt.status: FAILED
attempt.error_kind: asset_revoked
attempt.usage_status: UNAVAILABLE
attempt.uncached_input_tokens: null
attempt.output_tokens: null
```

建议保留 FAILED/asset_revoked 及不采用响应的业务语义，但将已收到的 response 传给 finish_attempt，保留实际 usage 并按实际使用量结算。增加“请求在途撤销、供应商仍返回有效 usage”的测试，验证失败状态、usage 完整、无后续重试及不选中该响应。无需调整 JEV 预算策略。

# 跟进与每日复盘意图：真实模型基线验收

日期：2026-09-20。

结论：**模型能识别明确的每日复盘要求，但模糊委托、跨目标信息及工具能力边界仍有缺口；本轮基线未达到开发文档的全部门槛。** 不能把结构化探针成绩视为线上业务执行成绩。

## 1. 实际执行

- 数据：42 个预先标注场景；旅游、健身、学习、工作、生活和边界对话。分布：none 20、once 5、daily 8、weekly 3、stop 4、clarify 2。
- 模型：现有配置 `deepseek-flash`，实际请求发送至 `api.deepseek.com`，没有 mock。供应商内部模型修订号未由现有网关返回。
- 双层运行：42 次意图探针 + 42 个现有聊天适配器回放；后者含 3 次追加调用，共 **87 次真实 API 调用**。
- 温度 0，thinking=false；并发上限 3；网关 max_attempts=1、network_retries=0；输出上限探针 450、聊天 1800；超时 90 秒。
- 所有 87 次 API 均成功返回，0 次截断；探针中 3 例违反 JSON-only 输出协议。
- 实际起止及配置、数据/代码 hash：见 `docs/evaluation/followup-intent-v1/live-01/results.json`。

本轮没有改生产提示词、Runtime 或业务工具，没有创建真实用户目标。聊天测试止于 LiveConversationModel 返回值，没有执行 Worker、写入、审批或调度。

## 3. 失败证据与解释

| ID | 输入要点 | 实际问题 | 解释/下一步 |
| --- | --- | --- | --- |
| B01 | “接下来你每天带着我走吧” | 探针直接判 daily | 持续陪伴不等于每日复盘；应澄清服务形式。实际聊天有 ask_user，但问题主要针对背景 |
| B06 | 健身继续每日复盘；新露营只交付内容 | 探针 review=daily | 存在多目标扁平输出缺陷，不能直接认定模型误改露营。实际聊天正确只生成露营攻略；需目标级标签与授权隔离 |
| T03 | 保存攻略，不要每天问玩得如何 | JSON 后继续生成攻略，且头部 tracking=disable、review=stop | 未开启前的否定被解释为取消；同时输出契约冲突 |
| T06、F07 | 修改攻略；添加自行复盘日志 | 正确 JSON 后追加正文 | 生产文档指令影响探针 JSON-only 契约；不是复盘语义本身错误 |
| T08 | 明天提醒预约门票 | tracking=enable，理由称“一次性持续跟踪” | 单次提醒与进度跟踪混淆；实际聊天还无工具承诺会提醒 |
| L06 | 每天提醒背单词，不问进度或总结 | tracking=enable | 提醒应独立建模，但本次探针“持续服务”定义过宽；不能全归责模型 |
| B03 | 不再总结，保留进度记录 | tracking=enable | 保持已有状态与本次新增操作混淆；review=stop 正确 |
| B08 | 已有每周复盘，改成每天 | tracking=none，而金标 enable | 金标与“保留既有跟踪用 none”存在歧义。本轮冻结结果不修改；review=daily 正确 |

完整原始输出：`live-01/<ID>-probe-call-01.json`。失败 ID 全量保留，未用重跑成功替换。

## 4. 分离语义错误与格式错误

对 T03、T06、F07 仅离线解析输出开头的完整 JSON 对象，保留后续违规正文，不改主结果，不追加模型调用。诊断结果：

- 三维语义匹配 35/42（83.3%）。
- review 语义匹配 39/42（92.9%）。
- document 语义匹配 42/42（100%）。
- daily 仍为 TP=8、FP=2、FN=0。

这表明部分失败来自格式冲突，而非模型完全不理解请求。此诊断不能取代严格可执行输出成绩。

探针本身追加了明确标签定义，属于测量装置，不是线上已有分类器。后续需要将“目标对象、提醒、跟踪操作、复盘频率、当前生效状态”区分清楚，再用新版本数据验证。

## 5. 真实聊天行为

42/42 首轮成功返回，5/5 单次复盘案例调用 review_check_in，其余 37 例未调用该工具。明确的纯攻略、模板和菜单没有出现已开启每日复盘的承诺。

不能因此判定聊天入口已正确执行服务：

1. **执行管理被降为文字建议**：F03、L02、W02 没有把请求接入目标业务能力，回答手动维护文档或提供记录方法。
2. **无工具承诺副作用**：T08 说“明天上午 8:00 提醒你”；L08 说“已按你的要求处理…停止学习进度跟踪”，没有工具或配置回执。
3. **偏好接受与系统取消混淆**：F08、B03 接受取消复盘，却展示类似已变更状态；只能证明对话层理解，不能证明既有调度已取消。H04 相比之下明确提醒用户底层任务仍需另行关闭。
4. **频率承接并非总是可观察**：F04/F06 只问背景，首轮无法判断每日/每周频率是否被可靠保存。
5. **跨轮调整不彻底**：B04 识别每日，但保留历史“原计划不跟进”约束；B08 在用户要求改成每日后额外保留周日汇总。

逐例证据见 `docs/evaluation/followup-intent-v1/behavior-review.md`。本轮没有实际业务状态修改，因此不报告业务误写入率为零，不报告调度执行成功率。

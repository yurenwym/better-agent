## 1. 当前基线与目标

依据：[任务进度与问题清单](./V3-任务进度与问题清单-2026-09-22.md)、[历史验收报告](./acceptance/learning-v3-acceptance-2026-09-21.md)，以及本次对工作区代码的只读核对。

当前结论：V3 主体已实现，历史真实模型验收 21/21 通过，但生产自进化闭环尚未完成。历史成绩不能替代本轮验收。

| 项目 | 已知状态 | 本轮需要补齐 |
| --- | --- | --- |
| PostgreSQL | V3 集成测试已有 4 项，历史运行被 compose 环境阻断 | 独立测试库上的真实执行与结果 |
| 预算 | 历史模型验收使用预算替身 | PostgreSQL 预留、结算、恢复和回放成本验证 |
| 运行时 replay | `startup.py` 构造 pipeline 时未传 replay；默认值为 `None` | 正式启动入口可用的回放数据与执行器 |
| Skill 迭代 | Adapter 默认版本为 `1.0.0` | 同名新内容的版本演进、并发和幂等 |
| 失败语义 | 模型 dispatch 后的异常保守归为 UNKNOWN | 区分确定无写入的拒绝与执行结果未知 |
| Memory 来源 | Experience ID 无法直接充当 Memory 用户证据 | Experience 到原始用户来源的可追溯映射 |
| Behavior | 只有 prompt 子类型有已知完整发布通路 | 审批、Canary 调度、真实收敛与回滚 |
| Legacy | 仍保留旧入口和分支 | 发布稳定后逐来源迁移，再删除旧逻辑 |

目标：系统能够从真实来源产生候选、执行可追溯评估、在授权范围内晋升，并在失败、重启、并发或证据撤回时保持可解释、可恢复、无重复应用。

### 必须保持的约束

- JEV 负责决策，LLM 负责生成，Judge 提供评估信号，Harness 决定最终晋升。
- 不降低证据、权限、回放或 Canary 门槛来换取通过；Memory 继续要求可信用户来源。
- Shadow 允许暂存候选和审计记录，禁止修改生产启用版本、live channel 和 runtime bundle。
- UNKNOWN 不自动重放；无副作用的拒绝也必须保留已发生的模型调用与费用记录。
- PostgreSQL 集成 fixture 会清空应用表，只允许访问专用测试库。
- 旧验收报告保留为历史证据；新一轮使用独立结果目录，不覆盖冻结计划。

### T03 — 验证真实预算与崩溃恢复

- **依赖**：T02。
- **位置**：`backend/app/learning.py`、`backend/app/costs.py`、`backend/tests/integration/test_root_task_budgets.py`；必要时新增学习预算集成用例。
- **动作**：使用真实 PostgreSQL 预算服务，覆盖预留、结算、额度不足、重复请求、dispatch 前失败、dispatch 后结果未知。
- **动作**：确认 JEV、生成、Judge 及后续 replay 的收费调用有明确归属，不能通过新执行器绕过预算；验收脚本移除预算替身的路径留到 T16 验证。
- **验收**：超预算时不继续调用；幂等重试不重复扣费；UNKNOWN 不自动再调用；已发生的成本不会因候选被拒绝而被错误撤销。
- **产物**：预算状态转换与故障场景记录；全量既有成本失败逐项归因，不默认沿用历史归因。

### T04 — 定义并实现运行时 replay 数据提供器

- **依赖**：T03。
- **位置**：`backend/app/learning_pipeline.py::_evaluate`、`backend/app/learning_eval.py`；优先复用项目已有回放能力，必要时新增 `backend/app/learning_replay.py`。
- **动作**：沿用现有 `replay(target, candidate) -> (cases, runner)` 接口，明确 owner、candidate、champion 版本和冻结数据集的绑定方式。
- **动作**：Skill 提供相关任务和无关任务；Behavior 使用冻结评估集，区分 DISCOVERY 和评估数据，禁止把同一来源重复计为独立证据。
- **动作**：记录数据集摘要、用例 ID、候选内容摘要、基线版本、模型配置；不可用时输出可操作原因。
- **验收**：同一评估能定位到相同冻结输入；跨 owner 数据不可混用；空集或不完整集合不能成为 PASS。

### T05 — 实现有预算约束的真实回放执行器

- **依赖**：T04。
- **位置**：T04 的提供器、`learning_eval.py::skill_replay_metrics` / `behavior_replay_metrics`、已有任务执行与预算接口。
- **动作**：在隔离评估上下文中运行 candidate 和 champion，收集成功率、触发情况、成本、安全结果及 Judge 输入。
- **动作**：候选以评估身份加载，不能为了回放而启用生产 Skill 或切换 stable bundle；限制回放工具副作用。
- **动作**：超时、运行失败、预算不足均记录结构化原因，禁止返回伪造的成功指标。
- **验收**：测试可证实候选内容确实参与执行，替换候选会改变对应执行输入；回放成本进入真实账本，生产资产无变化。

### T06 — 从正式启动入口接通 replay

- **依赖**：T05。
- **位置**：`backend/app/startup.py`、`backend/app/learning_pipeline.py::build_pipeline`、`backend/tests/test_learning_v3_wiring.py`。
- **动作**：由启动组装点注入真实 replay provider；明确配置和能力状态，区分“没有配置提供器”和“该候选没有适用数据集”。
- **动作**：对已配置开放的目标检查必要能力；缺失时给出明确阻断原因，不静默宣称已具备自动学习能力。
- **验收**：通过 `build_runtime` 创建的 Skill / Behavior 流程实际进入 replay；缺失数据集仍安全停在 NEEDS_REPLAY；OFF / SHADOW / ACTIVE 行为保持可解释。

### T07 — 补齐等待回放、审批后的续行

- **依赖**：T06。
- **位置**：`learning_pipeline.py`、`learning_promotion.py`、学习任务调度与现有审批接口。
- **动作**：核对 NEEDS_REPLAY、PENDING_APPROVAL、PENDING_RELEASE_EVALUATION 的后续入口；不能只记录终态后永久搁置。
- **动作**：为仍有效的已有候选提供重新评估或审批后推进入口，沿用候选身份，追加新评估记录；核对内容、证据、基线和审批是否过期。
- **动作**：过期或来源变化时拒绝续行并说明重建条件；UNKNOWN 仍禁止自动重放。
- **验收**：补充回放或有效审批后无需重新生成候选即可前进；重复续行不重复晋升；重启后仍能找到待处理项。

### T08 — 精确分类候选创建失败

- **依赖**：T07。

- **动作**：逐个检查冲突抛出位置的数据库和文件系统副作用，建立“确定未写入 / 已完成 / 结果未知”的依据。
- **动作**：只对能够证明未写入的校验拒绝增加明确错误类型或错误码，由流水线映射为 REJECTED；禁止将所有 `ValueError` 或安装异常统一降为 REJECTED。
- **验收**：preview 冲突不再误记 UNKNOWN；模拟写入途中异常仍为 UNKNOWN；模型调用费用和审计保留。

### T09 — 支持 Skill 候选版本演进

- **依赖**：T08。
- **位置**：`learning_targets.py::SkillTargetAdapter.create_candidate`、`skill_platform.py`，必要时数据库迁移。
- **动作**：以 owner、skill 身份、基线版本及候选内容定义版本策略；不能继续让所有新内容落到默认 `1.0.0`。
- **动作**：同一 job 重试复用原候选；相同内容避免无意义的新版本；不同内容产生合法且不同的版本。选择与现有版本解析、排序兼容的方案并写入实现说明。
- **动作**：用数据库约束和事务处理并发分配，不能只靠“读取最大版本再加一”；不覆盖或自动启用当前生产版本。
- **验收**：同名两轮不同内容均可暂存；重复 job 不新增；并发候选无版本覆盖；晋升后回滚能恢复上一启用版本。

### T11 — 建立 Experience 到用户证据的映射

- **动作**：保留 Experience → 原始来源 → Memory proposal/revision 的审计链；不得将 agent 总结伪装为用户发言。
- **验收**：合法 Experience 可产出有效 Memory proposal；只有 agent 推理、跨 owner、来源丢失或已撤回的输入不能写入记忆。

### T12 — 验证 Memory 证据变化与回滚

- **验收**：晋升前再次验证来源；证据不足不晋升；重复学习不重复写入；回滚与后续用户修改的版本冲突得到正确处理。

- **动作**：审批绑定候选内容、目标、评估及有效期；配置策略由可信管理路径设置，模型不得修改。
- **验收**：关闭的目标无法通过直接 API 或续行入口晋升；过期、跨 owner 或内容不匹配审批无效；停用学习与回滚已应用资产的语义分别写明。

### T14 — 接通 Canary 的周期推进与恢复

- **验收**：审批后的合法 prompt 候选可进入 Canary；样本不足不晋升；失败或到期有明确退出状态；重启不丢失进度，不重复修改 stable。

### T15 — 验证真实 release 生命周期

### T17 — 第一阶段发布：Memory

- **依赖**：T16；执行时具备明确的生产发布授权。
- **动作**：先限定 owner/项目范围开放 Memory；确认配置不会同时开放 Skill / Behavior。记录变更前资产版本和暂停方式。

- **退出条件**：跨 owner 写入、无可信用户证据写入、重复应用任一出现即停止该目标，调查并恢复受影响资产。

### T18 — 第二阶段发布：Skill

- **依赖**：T17 观察通过；执行时具备相应发布授权。
- **动作**：开放有限范围 Skill 候选审批与启用，验证相关任务改善和无关任务误触发，完成至少两轮版本演进。
- **验收**：沿用冻结的成功率、Judge、误触发与成本门槛；审批前不启用；第二轮候选不覆盖第一轮；可回退上一版本。
- **退出条件**：权限扩大、未审批启用、成功率回退或误触发超过门槛时停止晋升并回滚。

### T19 — 第三阶段发布：Behavior Canary

- **依赖**：T18 观察通过、T15 完成；执行时具备相应发布授权。
- **动作**：仅开放已验证的 prompt 通路；冻结流量比例、预算、deadline、角色和用途，真实积累至少 20/20 样本并执行既有门禁。
- **验收**：生产 release 生命周期有完整证据；通过后仅晋升一次，失败时停止/回滚。样本不足或期限到达不能被当作默认批准。
- **产物**：生产观察报告，明确开放范围、样本窗口、结果与回滚状态。各阶段观察窗口和最低有效样本在发布前冻结，不事后按结果调整。

### T20 — 建立 Legacy 逐来源迁移契约

- **依赖**：T19 稳定；独立开发批次。
- **位置**：`learning_legacy.py::execute_legacy`、`learning.py::scan / execute`、`test_learning_v2.py`。
- **动作**：以当前代码为准盘点 `prompt_cycle`、`behavior_candidate`、`goal_review`、`method_feedback`、`research_result`，以及默认消息来源。
- **动作**：为每一来源明确转换后的输入、证据、目标决策、幂等键和原有可观察行为；不能按来源名称强制推定目标。
- **动作**：明确存量 QUEUED、已 dispatch、UNKNOWN 作业在切换时的处理；UNKNOWN 不重放。
- **验收**：每个旧入口都有兼容测试和迁移对应项；先保留旧测试，不以删除测试消除回归。

### T21 — 逐来源切换到统一流水线

- **依赖**：T20。
- **动作**：一次迁移一个来源：转换为统一输入 → 产生 typed candidate → 评估 → 晋升门禁。先验证再切换生产分派。
- **动作**：取消对应旧入口的直接 apply；防止新旧 scan 对同一来源重复建任务；对旧方法的直接测试逐步改为等价行为测试，必要时短期保留薄兼容包装。
- **验收**：五类来源和默认消息路径均通过兼容验证；不能绕过证据、预算、审批、回放或 Canary；切换期间无重复资产和丢失任务。

### T22 — 删除旧实现并完成交付收尾

- **依赖**：T21，全量回归完成。
- **动作**：确认调用引用、存量队列和回滚依赖后删除不再使用的分派与实现；更新架构、配置、测试和运维说明。
- **动作**：把原“保留旧测试”解释为保留行为保障，记录测试迁移对照；不为满足删除步骤直接破坏兼容性。
- **验收**：学习入口统一，无旧直写路径；新旧行为契约可对照；交付文件进入可复现版本管理快照。
- **范围外**：历史 `outputs/` 批量清理另行处理，不属于自进化机制完成条件。

日期：2026-09-21。依据：用户提供的原简历截图、当前工作区代码与已有验收记录。范围仅为 Better Agent 项目段落，未修改完整简历。暂沿用原稿“AI 全栈开发”角色，内容优先面向 AI 应用 / Agent 岗位；新增模块的个人职责需由本人核对。本次未重新运行模型评测，以下数字引用已有报告。

## 可替换文案

**Better Agent｜AI 全栈开发**

**项目描述：** 面向个人任务的本地 Agent 平台，支持需求澄清、深度研究、计划生成与执行管理，通过长期记忆、工具调用和人工审批承接多轮任务。

**技术栈：** Python、FastAPI、React、TypeScript、PostgreSQL / pgvector、SSE、MCP。

- **可恢复的 Agent 任务引擎：** 基于持久化状态机、执行检查点与步骤级 ReAct 循环，串联澄清、规划、执行与复盘，支持计划修订、中断恢复及 SSE 实时追踪；统一接入业务工具与 MCP，通过写入审批、幂等键和执行回执防止重复副作用，对结果不确定的操作转入核对流程。
- **上下文工程：** 按系统约束、任务状态、承接摘要、近期对话与检索记忆分层组装上下文，以完整轮次和工具调用对为原子单元；摘要提交后再替换历史原文，保护近期对话并校验最终请求预算，避免静默截断关键信息；完成含长输入与澄清续接的 16/16 轮真实模型对话验收。
- **记忆系统：** 构建短期对话、情景摘要与长期记忆三层机制，结合自动归档、用户确认写入、版本管理及用户/项目隔离；采用 pgvector HNSW 与关键词召回、RRF 融合排序，并通过规则与按需模型调用补全指代；在 52 道构造留出题上，严格回答正确数由 43 提升至 49。
- **多 Agent 协作与自进化：** 实现研究、规划、审查专家的并行分发与结果汇总，通过上下文快照、心跳租约和结构化产物校验支持故障恢复；汇集任务结果与用户反馈形成经验，构建候选生成、配对评测、人工审批、灰度与回滚机制，将进化约束在获准的提示词片段或角色路由配置内。

## 改写理由

1. 按用户指定的四条主线组织：可恢复的 Agent 任务引擎、上下文工程、记忆系统、多 Agent 协作与自进化。
2. 上下文工程侧重单次请求如何完整、受预算约束地组装；记忆系统侧重信息如何持久保存、确认、隔离和召回，避免两条重复。
3. MCP 与业务工具归入任务引擎，不单独占用一条。MCP 真实模型成功证据明确为 stdio、只读工具，不延伸为远程 HTTP 或第三方业务写入的完整验证。
4. 当前费用模式默认 observe，不描述成默认按金额上限拦截。上下文容量预算和费用预算是不同机制。
5. 自进化写为已实现的受控机制，不宣称已完成生产晋升或获得真实业务质量提升。

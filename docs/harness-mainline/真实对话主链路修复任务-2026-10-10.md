日期：2026-10-10。状态：F01—F10 已完成，四项修复通过对应真实复测及回归。

## 1. 目标与范围

修复本地真实对话暴露的四项问题：长会话整理后续跑、对话标记行动完成、激活预览重复审批、工具英文开场。

本轮不处理深度研究，包括检索、研究取消时延与取消后发送核查；不增加评测平台、Learning 或 Runtime 重构。无需部署。

已完成的局部修复（复盘数据传递、交接消息收尾等）不是本文任务的完成证据。实施前保留工作区现有修改，不覆盖、不回退。真实测试记录位于 `outputs/live-journey-20261010/RESULTS.md`，该目录可能不受 Git 跟踪。

## 2. 开发约束

1. 复用 AgentLoop、TaskRuntime、PolicyEngine、审批、幂等执行与领域服务；禁止第二套调度器、完成逻辑或授权入口。
2. 优先小函数和明确参数。新增抽象、状态、字段必须有本任务生产调用方，不做通用化扩展。
3. 身份、项目范围、版本、预算、取消和租约校验不得交给模型决定。模型不得提供可信身份字段。
4. 数据库变更使用迁移，明确旧数据与在途任务兼容；不得清空历史或只在新数据库上验证。
5. 每个任务完成实现、必要回归和简短记录后再进入下一项。记录真实测试结果，禁止用 mock 通过代替线上模型体验。
6. 不通过截断必需历史、忽略审批、无限等待、无限重试或改写模型输出字符串掩盖问题。
7. 付费复测设置可执行预算与次数上限；建议本轮总额不超过 $0.50，只重测受影响场景，保留调用结果避免重复付费。

## 5. F02：历史整理脱离短等待取消

当前 `_archive_attempt_once` 可能直接执行归档，外层 `asyncio.wait_for` 使用前台等待期限。应分离界面等待和归档任务生命周期。

- [x] 前台负责幂等入队与观察；现有归档 worker 负责领取、处理和结果提交。
- [x] 等待时即可显示“正在整理历史”提示；2 秒不再是执行期限，不因提示阈值取消归档调用。
- [x] 同一历史前缀复用已有整理任务，不重复领取、重复发送或重复提交。
- [x] 梳理前台优先级规则，避免“等待归档的对话”反过来阻止归档 worker 执行。
- [x] 区分整理失败、预算不足、无可整理前缀与仍在处理中；保留明确终态。

**验收：**受控整理耗时大于 2 秒仍能完成；同一前缀只有一次有效提交；失败原因可见，缺失历史不能进入回答阶段。

- [x] 用户明确请求生成预览时无需前置审批；保留身份、预算、幂等和写入对账。

- [x] 预览或源文档变化使旧审批失效；不得自动换成最新内容执行。
- [x] 口头“确认”可触发审批卡，不再出现“先口头确认、再点另一张确认卡”的额外要求。

### 实际限制与修复边界

- 当前供应商到响应结束才能可靠确定工具调用，因此普通回答也缓冲到完整响应后再展示。上述首字时间来自单个短回答，没有声称缓冲无成本，也没有做不同模型的延迟比较。
- 受保护的最近历史本身超过模型容量时仍会失败，保留输入并显示容量问题；不能通过丢弃历史或反复付费整理绕过。
- 真实短计划编译曾输出无效 JSON、3/4 分钟行动；保留校验，增加短计划合并子步骤的约束后同一文档重试成功。未来不保证模型永不输出无效结构。
- 完成及部分进展没有新建复盘。随后显式 `close_day` 才产生并完成真实复盘，调整建议仍待用户决定。
- 测试记录区分自然对话与人工构造历史的恢复案例；未启动新的深度研究测试。`research/web.py` 及其测试的工作区修改来自本轮开始之前。

## 目标

用户在对话中调用能力；短操作直接返回，深度研究等长任务返回任务引用，支持查询、取消、重启恢复和结果回传。权限、审批、预算、执行结果和轨迹具有统一边界。

基于现有 AgentLoop、HarnessExecutionContext、ExecutionOutcome、EventMetadata 和领域服务渐进迁移。保留现有用户流程与历史记录。

## 统一代码约束

1. 纯契约只依赖标准库与现有纯类型。领域/基础设施适配层依赖契约；契约不得反向导入 DB、HTTP、网关或服务。
2. 新枚举、接口、字段必须有本任务生产调用方。使用明确类型与受限字段；禁止万能 dict、字符串解析控制流、通用插件框架。
3. 复用当前身份工厂及持久化校验，模型参数不能提供 owner、trace、lease token、审批凭据或预算权限。
4. PolicyEngine 决策；Executor 执行能力；TaskRuntime 管任务执行权；领域服务管理业务状态。每个状态和副作用只有一个权威写入者。
5. 不增加通用重试器。模型重试属于网关，任务恢复属于 TaskRuntime，工具 unknown 副作用只能走原对账流程。
6. 关键状态、结果及事件同事务；通知和统计投影在提交后更新。禁止异常吞掉后继续缺少授权/审计的写操作。
7. 迁移使用最小适配器；一个入口同一时刻只有一个执行实现。不得双 worker 抢同一任务，不得复制审批或 claim 表形成第二套事实来源。
8. 不用删除旧异常或压缩行数作为“优美”指标；以单向依赖、清晰职责、显式不变量和故障可解释性为准。
9. 可保留有使用者的兼容接口，每个接口写明调用方与删除条件。不得顺手重写无关模块。

## 验证与交付纪律

- 每个任务记录修改文件、聚焦测试命令、真实结果、兼容/迁移方式和剩余问题，写入 [开发记录](implementation-notes.md)。
- 重点测外部可观察行为：发送次数、执行权、持久化结果、事务回滚、跨用户拒绝、重启恢复。避免只验证实现细节的镜像测试。
- 竞争与事务测试使用隔离 PostgreSQL；SQLite 只作既有兼容测试。
- 中间任务跑聚焦测试；每阶段门禁和每次准备提交前运行仓库根目录 `python scripts/test_all.py`。失败归零，逐项说明 skip，不为通过而新增 skip。
- 全量门禁前收束代码；测试期间有代码修改，该日志不能作为最终固定版本通过依据。
- 默认确定性模型和本地假工具。仅 A06 必要时进行小规模真实 smoke；沿用既有授权和预算机制，先写明单次/总额/次数硬上限，持久化后才调用，不扩展到评测支线。
- 每阶段可单独审查与提交；本文件不自动授权推送或生产部署。
- 新增生产 schema 通过 Alembic 迁移，明确旧数据读取、在途任务切换及回退限制。禁止自动清空历史。

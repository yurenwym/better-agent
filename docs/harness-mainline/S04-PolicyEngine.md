# 阶段 4：统一 PolicyEngine

前置 C04。核心边界：**纯决策 + 可信事实读取 + 现有执行器落地**。
PolicyEngine 不读取模型自报权限，不创建审批、不扣款、不执行工具、不睡眠重试。

## P01：定义最小决策契约

- [x] 盘点 tools.authorize、chat_tools、goal_loop、模型网关、来源快照和成本服务的现有规则。
- [x] 定义不可变 PolicyInput/PolicyDecision，建议决定为 allow、deny、require_approval；稳定 reason_code。
- [x] input 包含动作种类、可信身份引用、能力版本/风险、审批验证结果、来源有效性及预算可用事实。只添加真实消费字段。
- [x] 不可用事实按拒绝处理；明确多条规则冲突优先级，deny 优先于 require_approval。
- 交付：建议 policy_engine.py（纯类型/规则），适配层负责读取现有权威服务。
- 验收：同输入同结果；缺事实、冲突规则、未知能力均有确定结果；不触发 I/O。

## P02：接入一个只读能力

- [x] 选择现有对话只读工具，使用 PolicyEngine 判断允许范围和身份。
- [x] 读取当前持久化身份及能力定义；保持原 ToolResult 与用户文案。
- [x] 拒绝映射统一 Outcome；最小必要策略记录使用已有 EventMetadata，避免重复记录同一决定。
- 验收：合法调用一次；跨用户/未注册能力/来源失效零发送；无新审批或重试路径。
- 约束：该任务必须有生产消费者，不能只交类型。

## P03：接入写能力与审批恢复

- [x] 将审批“是否需要/是否满足”的判定迁移到纯规则，实际创建与决定仍调用 ApprovalService。
- [x] 审批绑定原能力版本、参数摘要和逻辑操作；恢复重新获取当前权限与来源事实。
- [x] 复用 ToolExecutionContext、原 claim 和对账；unknown 不受 allow 覆盖。
- 验收：等待审批零副作用；批准后一次写入；批准后撤权/参数变更/能力变更拒绝；重启不重复。

## P04：接入实际发送与模型重试边界

- [x] 网关每次真正发送/重试前刷新必要事实，调用同一决策语义。
- [x] 覆盖预检之后来源撤销、预算耗尽、任务取消和执行权丢失。
- [x] 预算读取只用于决策，原成本服务在实际发送前原子预留，allow 不等于额度已锁定。
- [x] 保留原模型重试次数、价格快照、来源依赖检查；不缓存 allow 跨越等待或重试。
- 验收：预检后撤销零发送；第一次失败后撤销禁止第二次发送；并发预算不超发；未知写入不自动重试。
- 限制：明确检查到发送之间的边界；不声称数据库能与远端副作用组成原子事务。

## P05：收敛主链路并做阶段门禁

- [x] 对话/目标/研究/专家交接使用同一决策规则；保留领域特有事实适配。
- [x] 删除已迁移重复判断，列明保留的防御校验与真正不同职责。
- [x] 完成允许/拒绝/审批矩阵、全量回归与简短接口说明。
- 验收：规则改变只有一个权威定义；无权限扩大、审批绕过、预算重置或额外模型调用。

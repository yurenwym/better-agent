# 阶段 6：统一任务运行机制

前置 E05。TaskRuntime 管领取、租约、心跳、执行尝试、取消、恢复和提交结果；业务服务仍管研究报告、专家 fan-out/join、对话消息和目标计划。

**worker lease 与工具执行 claim 分开。** 前者防过期 worker 提交，后者防外部副作用重复。lease_epoch、任务 attempt、模型 retry ordinal 也不能混用。

## R01：盘点与选定存储权威

- [x] 用源码核实所有 claim/lease：对话队列、研究、专家、现有 DurableQueue，以及其他后台任务。
- [x] 分类为 worker 执行权、工具幂等、预算预留、业务锁；禁止机械合表。
- [x] 为每类列出 owner/epoch/deadline/attempt/取消/恢复/提交约束及生产调用方。
- [x] 优先复用现有通用队列；若新增最小任务执行表，写明必要性和旧字段退出计划。
- 交付：逐类迁移表、唯一调度权威、在途任务切换方案。
- 验收：先迁移研究；随后专家、对话。非主链路任务明确延后，不宣称所有后台系统已统一。

## R02：最小租约内核

- [x] 定义 TaskRef、LeaseToken、TaskAttempt；token 包含 task/worker/epoch，完全来自服务端。
- [x] 实现 claim、heartbeat、finish、request_cancel，使用条件更新或数据库行锁。
- [x] 领取递增 epoch；心跳不得复活过期租约；提交检查当前 token、取消状态和截止时间。
- [x] 状态/Outcome/事件同事务；重复同结果复用，冲突终态拒绝。业务回调使用同一事务连接。
- 验收：真实 PostgreSQL 双 worker 竞争、租约过期重领、旧 token 心跳/提交拒绝、完成与取消竞争、故障回滚。
- 禁止：全局内存锁代替 DB 执行权；新通用调度平台。

## R03：研究任务纵向迁移

- [x] research/service.py 与 worker.py 接入租约内核；任务参数、限额、报告及来源快照仍由研究服务拥有。
- [x] 数据库迁移只补必要字段；旧在途任务由旧路径排空或显式映射，禁止两种 worker 同时领取。
- [x] 从原 source_turn 继承身份；失去 lease 后停止后续模型发送，迟到报告不能发布。
- 验收：对话启动研究、进度、取消、崩溃恢复、迟到报告拒绝；模型费用记录与根预算不重置。
- 交付：第一条完整 TaskRuntime 生产路径及独立切换/回退说明。

## R04：专家任务迁移

- [x] 专家 claim/heartbeat/finish 接入内核，保留业务 fan-out、join、部分失败和综合规则。
- [x] coordinator 和 child 各自持有执行权，父子关系、trace、预算继承不变。
- [x] 任一过期 child/coordinator 不得覆写产物或重复回传。
- 验收：ALL_DONE/ALL_SUCCESS、部分失败、重启综合、取消/接管竞争、跨 owner 拒绝。
- 禁止：为此重写专家 prompt 或合并业务状态机。

## R05：对话 worker 迁移

- [x] 适配现有 DurableQueue/turn_jobs，保留用户消息、stream generation、审批续接和上下文打包行为。
- [x] 丢失 lease 后禁止继续发送或把已废弃文本标记为最终；SSE 游标与重连兼容。
- [x] 恢复从已提交状态读取，不重新创建 trace 或预算。
- 验收：多 worker 竞争、流式取消、断线重连、审批等待后重启、旧 worker 迟到消息拒绝。

## R06：目标与在途迁移收尾

- [x] 判断目标执行是任务租约还是现有同步调用；仅真实异步执行权接入 TaskRuntime。
- [x] 保留目标计划、检查点、等待外部结果等领域状态。
- [x] unknown 工具 claim 始终进入对账，重新取得任务租约不得授权重新写入。
- [x] 验证老版本在途任务与新任务混合存在、重复启动和恢复；回退禁止恢复旧 worker 的并行执行权。
- 验收：迁移清单中每项有完成/延后理由；主链路没有两套独立领取决策。

- [x] 核对旧事件读取、数据库迁移和运行配置；删除已迁移重复租约算法。
- [x] 运行完整门禁并记录。
- 验收：统一机制已有上述真实生产消费者；未迁移的辅助后台任务明确列出，不以“七套合一”口号替代证据。

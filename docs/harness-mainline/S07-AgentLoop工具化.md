# 阶段 7：现有 AgentLoop 接入任务型能力

前置 R07。实现用户主流程：对话启动深度研究 → 返回任务引用 → 查看进度/取消 → 完成后接收结果 → 继续对话。

复用 agent_loop.py、conversation_capabilities.py、goal_capabilities.py；不新建循环、研究引擎或评分平台。

## A01：最小任务能力契约

- [x] 复用现有 start_research/delegate_experts 名称与业务参数，定义其异步返回的 TaskRef。
- [x] 增加确有用户流程需要的查询和取消能力，名称在本任务一次性锁定；任务引用由服务端产生。
- [x] 任务排队成功返回 handoff，查询未完成返回明确状态，不能被当作任务 completed。
- [x] Executor 通过 PolicyEngine 校验任务 owner 和可操作范围。
- 验收：非法引用、跨用户引用、重复启动、重复取消行为明确；模型输入不能伪造执行权。

## A02：对话启动研究

- [x] 将现有研究 handoff 适配到 Registry/Executor/TaskRuntime，不另加关键词强制路由。
- [x] 启动提交成功后才返回任务引用与简短提示；当前对话 loop 可结束，研究继续后台执行。
- [x] 启动失败不得输出“已开始”；重复逻辑调用复用同一任务。
- 验收：明确研究请求、普通问答、歧义请求三类确定性对话；一次启动一个任务，trace/budget 可定位。

## A03：进度查询与取消

- [x] 通过任务能力读取已提交进度；避免展示内部 lease、堆栈和技术配置。
- [x] 用户后续消息能指定原任务；新回合拥有自己的 trace，操作事件明确关联目标任务。
- [x] 取消请求落库后阻断新发送；已发生但未知的写入保留对账义务。
- 验收：运行中/已完成/失败/已取消查询；取消与完成竞争；重复取消；不存在和外国用户任务拒绝。
- 约束：不自动高频轮询模型，不因查进度重复执行研究。

## A04：结果回传与继续对话

- [x] 复用当前报告与线程消息投影，在任务提交后回传结果；业务结果有唯一 delivery 幂等键。
- [x] 发布失败可从数据库恢复投影，不重跑模型；进程重启后仍可查/收结果。
- [x] 后续对话按现有上下文规则引用报告，不向新 prompt 无限制倾倒全部内部证据。
- 验收：报告完成后发布前崩溃、重复通知、用户已切换回合、线程删除、来源撤销；不得错误归属或重复消息。

## A05：专家与目标能力接入

- [x] 专家协作通过相同任务型契约启动/查询/取消/回传，保留各专家业务职责。
- [x] 目标操作继续使用阶段 5 的审批与 Executor；异步任务只通过阶段 6 接入。
- [x] 清理已迁移旁路，保留有明确调用方的兼容接口；不扩大为全仓 Runtime 重写。
- 验收：同一对话能分别发起研究、专家和目标操作；每条链的授权、Outcome、事件和副作用一致。

## A06：主链路发布门禁

- [x] 确定性端到端：普通回答、读工具、审批写入、研究启动/查询/取消/回传、专家协作、目标执行。
- [x] 故障端到端：撤权、预算不足、发送前撤销、租约接管、取消与迟到响应、重启、unknown 对账。
- [x] 每条同时检查结果、持久化状态、trace 和发送次数；完整 test_all 零失败。
- [x] 若工具 schema/prompt 的实际路由变化尚无真实验证，沿用已有授权做最小真实 smoke：先固化预算上限、最大尝试数和输入，逐次持久化；断点续跑不得重复付费。无需 20/60 例 Judge 评测。
- [x] 写清启动配置、迁移次序、在途处理、可回退范围、已知限制，更新任务状态。
- 验收：用户仅通过对话即可完成研究任务全生命周期；无需使用内部评测脚本；所有必需任务关闭后才标记整个计划完成。

## 一、最终目标

围绕现有“对话 → Agent 调用工具 → 任务执行 → 返回结果”主链路，交付以下结果：

| 最终目标 | 用户可观察行为 | 验收依据 |
| --- | --- | --- |
| 操作有权限边界 | 无权限、来源撤销或渠道禁用后，不继续发送或写入 | 拒绝场景零外发、零业务变更，保留必要拒绝审计 |
| 全流程可追踪 | 页面显示模型、工具、子任务及后台动作，能定位失败和重试 | 真实事件接入，缺失及截断明确标注，跨用户不可读 |
| 后台任务可恢复 | 超时或重启后由有效执行者处理，旧进程不能覆盖结果 | PostgreSQL 并发领取、接管、续租及提交保护测试 |
| 通知结果可信 | 已发送、失败、未知明确区分，不因超时重复通知 | 假 provider 发送计数与持久化状态对应 |
| 旧路径有序退出 | 新路径默认工作，旧路径显式控制，历史结果可读 | 使用遥测、真实观察、分批删除和回归验证 |
| 交付可复核 | 每个已交付任务有固定代码对应的验证记录 | 完整门禁、页面 E2E、迁移及回退说明 |

最终应能从页面完成：**创建计划 → 保存与审批 → 执行/查询/取消 → 显式 close_day → Agent 复盘**，并在轨迹页看到每一步发生了什么、为何失败、是否已经产生副作用。

### 范围边界

- 复用 AgentLoop、PolicyEngine、TaskRuntime、Event Envelope 和领域服务。
- 不新增研究评测、Judge 配对评分、RAG 产品、第二套审批、通用 Worker 平台或独立监控平台。
- 深度研究只验证任务接口兼容，不运行真实研究，不改研究算法。
- 默认确定性模型、假 provider 和隔离数据库；不以付费调用验证权限、并发和恢复逻辑。
- 本文不新增推送或部署授权，不改变产品审批等级。

## 三、代码与验收约束

1. Policy 决策，领域服务拥有业务状态，TaskRuntime 管执行权，Trace 读取及投影；一个状态只有一个权威写入者。
2. owner、审批、来源和租约来自持久化事实；不接受模型提供的权限事实，不为缺失身份默认 local-user。
3. 校验靠近实际发送与提交；竞争依赖现有事务、锁或条件更新。同一事务内普通 SELECT 不等于锁住来源。
4. 被请求引用的拒读资产不能只从依赖列表删除后继续发送；保留 P04 冻结、发送和重试前的检查。
5. 数据提交后执行文件投影，失败保留恢复意图；不能把已提交业务状态解释成未发生。
6. 关键状态和权威事件同事务。外部发送与数据库不能伪装成原子操作；UNKNOWN 不降为普通失败后自动重试。
7. 明确类型、短函数、单向依赖。仅对实际共性提取公共代码；不写空适配器、万能上下文或无调用接口。
8. 保留 revision/profile/content_hash、checkpoint、预算、来源、canary、审批和现有对账规则。
9. 事件使用必要字段白名单；不包含完整 prompt、密钥、凭证、敏感正文及模型内部推理。
10. 子任务必须验证生产调用路径与可观察结果，不能只测辅助函数；竞争与迁移使用隔离 PostgreSQL。
11. 中间任务跑聚焦回归，阶段结束及准备提交时跑完整门禁；不得通过删断言、扩大 skip 获得绿灯。
12. 每次完成一个纵向闭环：最小生产改动 → 回归测试 → 开发记录。不要同时铺开所有阶段。

以下路径相对仓库 D:/RAG/better；实施时确认真实文件和符号，不因文件已存在就标记接入完成。每个父任务须满足全部必需子任务、验收和完成条件后才能勾选。

# 对话全流程示例：从目标询问到受控自进化

> 本文为演示脚本与验收参考，不是实际运行记录。文中的“已保存”“已激活”“已确认”是示例对话；真实测试必须核对接口结果和持久化记录，不能仅凭回复文字判定成功。

示例目标：30 天内完成 Python 数据分析入门项目。

## 1. 询问

**Agent：**

为了制定可执行计划，请回答：

1. 你每天可投入多少时间？
2. 每周可学习几天？
3. 当前 Python 基础如何？
4. 你希望最终完成什么项目？
5. 计划从哪天开始？
6. 是否有必须避开的时间段？

**用户：**

每天 1 小时，每周 6 天。会基础语法，希望 30 天后完成一个“销售数据分析与可视化”项目。下周一开始，周日休息。

## 2. 回复与确认

**Agent：**

我理解你的目标是：

- 周期：30 个自然日。
- 每周投入：6 天，周日休息。
- 每天投入：1 小时。
- 起始时间：下周一，保存前按用户所在时区确认具体日期。
- 最终成果：销售数据分析与可视化项目。
- 当前水平：Python 基础。

我会按“基础巩固 → 数据处理 → 可视化 → 综合项目 → 复盘优化”拆分计划。你是否已经安装 Python、Jupyter 和 pandas？

**用户：**

Python 已安装，pandas 和 Jupyter 还没有。

## 3. 创建计划

**Agent：**

### 30 天 Python 数据分析计划

以下阶段按自然日划分；周日不安排学习任务，具体内容分配到阶段内的可用学习日，不把 30 个自然日误当成 30 个学习日。

| 阶段 | 时间 | 主要内容 | 验收产出 |
| --- | --- | --- | --- |
| 环境与基础巩固 | 第 1—5 天 | 安装 Jupyter、pandas、matplotlib；复习列表、字典、函数与文件读写 | 环境验证记录、3 个基础练习 |
| 数据处理 | 第 6—12 天 | CSV 读取、筛选、排序、分组、缺失值、日期与分类字段 | 清洗后的销售数据及处理代码 |
| 数据可视化 | 第 13—18 天 | 柱状图、折线图、饼图、散点图、美化与保存 | 可复现的示例图表 |
| 综合项目 | 第 19—26 天 | 选择数据集、设计问题、清洗分析、绘图、输出结论 | 4—6 张图表与分析初稿 |
| 整理与复盘 | 第 27—30 天 | 完善 Notebook、编写说明、检查代码、总结问题 | 可运行 Notebook、项目说明与复盘 |

执行规则：

- 每天安排一个核心任务，并附明确验收标准。
- 每日预算 60 分钟；超时应记录原因，不默认扩大用户承诺的时间。
- 连续两天未完成时，提出缩小任务范围的调整建议，确认后生效。
- 每 7 天进行阶段复盘。
- 每天记录完成情况、实际用时、难度、问题和产出。

这份计划是否确认？

**用户：**

确认。

## 4. 保存计划

**Agent：**

计划已保存：

- 名称：30 天 Python 数据分析入门。
- 版本：v1。
- 状态：已保存，待激活。
- 开始日期：已确认的下周一具体日期。
- 每日时长：60 分钟。
- 休息日：周日。

保存计划不代表授权执行。请先查看执行预览，确认日期和任务安排，是否现在激活？

**用户：**

激活。

**Agent：**

已激活。每日行动按确认的日程安排展示。

> 验收：核对计划 ID、版本、保存内容、执行预览与激活状态；刷新页面后仍可读取。保存失败时不得回复“已保存”。

## 5. 生成每日计划

**Agent：**

### 第 1 天：环境安装与验证

目标：完成环境安装与验证。

1. 安装 pandas 和 Jupyter。
2. 创建 `python-analysis` 文件夹。
3. 启动 Jupyter。
4. 编写并运行第一段代码。

验收标准：以下代码成功执行，并输出 pandas 版本。

```python
import pandas as pd
print(pd.__version__)
```

预计用时：60 分钟。安装问题持续超过 15 分钟时，记录错误并请求帮助。

> 验收：每日任务关联正确计划与版本，有日期、预计时长及验收标准；休息日无误排，重复生成不产生重复任务。

## 6. 执行每日计划

**用户：**

pandas 安装好了，但 Jupyter 启动失败，提示找不到命令。

**Agent：**

先确认终端使用的是你准备学习的 Python 环境，再执行：

```bash

```

如果仍失败，请提供脱敏后的错误信息，并检查：

```bash
python --version

```

**用户：**

第二条命令成功了，但安装花了 80 分钟，今天没有完成练习。

**Agent：**

今天记录为部分完成：

- 环境安装与 Jupyter 启动：完成。
- 第一段代码验证：未完成。
- 实际用时：80 分钟。

建议明天先补完验证，再根据剩余时间决定是否开始新内容；这会调整原日程，等待你的确认。

> 验收：用户完成学习任务，系统记录反馈；不能将打卡等同于 Agent 实际执行了代码。未通过验收的任务不能标为全部完成。

## 7. 每日复盘与调整

**Agent：**

### 第 1 天复盘

结果：环境已就绪，代码验证尚未完成；实际用时超过预算 20 分钟。

做得好的地方：能根据错误提示继续排查，完成了环境配置。

主要问题：

- 环境安装耗时超过预期。
- 原计划没有明确预留故障处理时间。
- 安装与学习任务同日安排，存在挤占学习时间的风险。

调整建议：

- 第 2 天先完成环境验证。
- 后续安装配置单独安排。
- 日常学习按 45 分钟核心任务加 15 分钟缓冲编排，总预算保持 60 分钟。

是否接受调整？

**用户：**

接受。

**Agent：**

调整已应用，保留旧版计划和本次调整原因。已完成记录不变，未完成任务按新安排执行。

> 验收：复盘引用真实行动、用时和用户反馈；调整有确认记录，不覆盖历史。复盘失败时保留执行进度，并提供重试入口。

## 8. 受控自进化

**Agent：**

今天的记录支持一项改进建议：安装配置任务应预留排障时间。但单次失败不足以证明你的长期偏好或习惯。

你是否希望今后的学习计划也采用“一个核心任务、明确验收标准、预留 15 分钟缓冲”的形式？

**用户：**

确认，以后的学习计划都这样安排。

**Agent：**

已记录你明确确认的学习计划偏好，作用范围仅限学习计划。今后可以修改或撤销。

若后续多次执行记录支持这一安排有效，系统可将其作为行为改进候选的证据；候选必须经过评测与批准，才能进入试运行，不会自动改写系统规则。

### 区分两种成长

- **用户记忆：** 明确确认的偏好可进入对应范围的记忆；推测的习惯仍需证据与确认。
- **系统行为进化：** 独立证据 → 候选生成 → 结构校验与安全检查 → 基线/候选评测 → 人工批准 → 小范围试运行 → 晋升或回滚。

没有充分证据或评测未通过时，保持现状也是正确结果。数据库、认证、网络和协议错误应进入工程排障，不能当成用户习惯或提示词进化收益。

## 9. 全流程状态变化

```text
询问 → 确认目标与约束 → 创建计划 → 用户确认 → 保存版本
  → 生成执行预览 → 用户激活 → 每日行动 → 执行与反馈
  → 每日复盘 → 调整提案 → 用户确认 → 更新后续安排
  → 提炼有证据的候选
      ├─ 用户偏好：确认 → 范围化记忆
      └─ 行为改进：评测 → 批准 → 试运行 → 晋升或回滚
```

## 10. 可能出现的问题与优化方案

| 问题 | 排查方向 | 优化方案 |
| --- | --- | --- |
| 计划过于宽泛 | 是否缺少任务产出与验收标准 | 每项任务增加可验证产出 |
| 保存后无法执行 | 区分保存成功、编译成功和激活成功 | 显示当前状态与下一步入口 |
| 每日任务经常超时 | 对比预计/实际用时及阻塞原因 | 在原时间预算内缩小核心任务并预留缓冲 |
| 日程与休息日冲突 | 检查时区、具体日期、自然日与学习日 | 按可用日编排并在激活前预览 |
| 遇到错误后计划中断 | 定位环境、网络、依赖或任务本身 | 附排障路径，保留进度，提供恢复入口 |
| 复盘只有主观结论 | 检查是否引用执行记录 | 记录状态、用时、难度、阻塞原因与产出 |
| Agent 擅自修改计划 | 检查提案、确认与版本记录 | 实质调整需确认，保留历史 |
| 错误被误判为用户习惯 | 检查证据来源和重复性 | 区分工程故障与用户行为，不从单次失败推断习惯 |
| 自进化规则过多 | 检查重复候选、作用范围与评测收益 | 去重、限制范围，无新证据则不变更 |
| 每日任务与长期目标脱节 | 检查计划、阶段和任务关联 | 每项行动映射阶段及最终成果 |
| 执行记录丢失 | 检查数据库写入、重试与重启恢复 | 持久化状态和事件，验证幂等性与恢复 |
| 模型角色路由缺失 | 核对已配置角色与模型能力 | 提前检查依赖，显示缺失角色，不虚报可用 |
| 自进化输出不合规 | 区分传输、JSON 解析与字段校验错误 | 脱敏诊断、有限重试；禁止无效候选进入评测 |
| 自进化失败阻断启动 | 检查测试种子是否在启动前强制生成候选 | 将主服务启动与进化验收分离 |

## 11. 测试记录要求

每个环节记录：操作、预期结果、实际结果、资源 ID、脱敏错误和结论（通过／失败／未测试）。

- 模拟模型通过不等于真实模型通过。
- 测试数据库通过不等于生产 PostgreSQL 通过。
- 前端构建通过不等于应用已启动。
- 某个阶段失败不代表其他阶段已经通过；未执行的阶段标记为未测试。
- 不把密钥、认证头或配置文件原文写入验收日志。

核心原则：状态变化可追踪，计划调整有确认，成长基于可核验证据，失败可恢复。

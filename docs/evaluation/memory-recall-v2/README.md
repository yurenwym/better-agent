# 长期记忆真实服务评测 v2

这是一组 **人工构造场景 + 真实 PostgreSQL、embedding 和 DeepSeek 调用** 的评测，不是用户真实日志，不代表生产准确率。v1 文件保持冻结。

## 数据及边界

- `memories.json`：168 条记忆，16 个服务各 8 条事实/旧值，另有 40 条干扰记忆。
- `cases.json`：100 道题及期望证据 ID、答案片段、禁止注入 ID、近期对话与预算；80 道有答案、20 道无答案。
- `manifest.json`：运行前冻结的参数和准入规则，随机种子 731902。
- dev 62 题、holdout 38 题；服务实体按问句切分互斥，索引语料共享。holdout 并不是完全不在索引中的未知实体。
- 覆盖精确数值、近义表达、错误码、两个必要事实、历史指代、无答案及 450/750/1500 字节预算。包含过期、归档、其他 owner/project 及同名预发布环境干扰。

## 实验设计

固定比较当前 legacy 排序与可选 RRF 排序（两路等权，k=60）。不改写查询、不使用 reranker、不调整预算；两组共享同一个真实查询向量，逐题交替调用顺序。生产默认仍为 legacy。

使用真实生产 selector，但回答阶段是独立评测提示词，不是完整 Agent 运行。评测器添加来源标签并按同一字节上限重新打包，因此同时保存 selected_ids 与 injected_ids。Recall@5 按预算选择后的 selected_ids 计算，不等同于原始数据库候选 Recall@5。

最多 200 次 DeepSeek 调用、268 次 embedding 调用，每个回答上限 256 tokens。模型为 `deepseek-flash`，温度 0、关闭 thinking；模型别名不能视为固定权重版本。embedding 为 `Qwen/Qwen3-Embedding-4B`、1024 维，当前配置超时 0.8 秒。

实际执行修订：建库时 6/168 请求超时，在任何回答测试开始前，实验统一改为 5 秒并仅补齐失败项；含失败的总调用上限调整为 274，实际累计 259 次。原 manifest 保留不改，修订见 `outputs/memory-recall-v2-pg-live-02/run_protocol.json`。应用默认超时未改。完整结果见 [v2 验收报告](../../acceptance/memory-recall-v2-live-2026-09-19.md)。

严格正确要求：答案包含全部标注片段、引用全部必要记忆，且所有引用均来自实际注入。无答案题必须返回 UNKNOWN 和空引用。原始回答与自动分保留；人工复核若发现字符串误判，应另列而不覆盖原始分。

## 运行与验收

入口为 `backend/scripts/memory_recall_eval_v2.py --execute --out <新目录>`。必须提供已迁移、空的独立 `better_memory_eval_*` 数据库配置 `MEMORY_EVAL_DATABASE_URL`，不得使用应用数据库。配置读取正常启动加载器，不再使用评测专属密钥别名补丁。

只有在留出集严格正确题数提高、精确值/错误码无退化且隔离违规为零时，才讨论启用 RRF。一次小样本通过也不等于完成生产上线验收。不得依据 holdout 结果调整本轮参数后重报为首次验收。

本轮没有覆盖完整 Agent、真实日志、独立双人 gold 复核、1K/10K 规模性能、逐条上下文注入改造；这些仍属于后续任务。

# RRF 与两路候选数量评测 v3

本轮回答两个问题：启用 RRF 能否改善回答；向量和关键词候选各取多少条比较合适。使用真实 PostgreSQL、SiliconFlow embedding 和 DeepSeek，题目仍为构造场景，不是生产用户日志。

已完成：3,200 次 dev 检索、208 次真实回答。新 holdout：legacy 50/50 为 43/52，RRF 50/50 为 49/52，legacy 10/100 为 42/52，RRF 10/20 为 47/52。见 [验收报告](../../acceptance/memory-recall-v3-topk-2026-09-19.md)、[32 组指标表](results-tables.md)、[新留出题目](holdout.md)。生产默认未切换。

## 冻结设计

- 272 条记忆：复用 v2 的 168 条及其真实向量，新增 104 条（8 个全新服务及干扰项）。在新独立数据库克隆测试语料，不修改生产库或旧实验库。
- 152 道题：v2 全部 100 题转作 dev；52 道新 holdout 题含 8 个新服务各 6 题和 4 道未知服务题。dev/holdout 服务实体互斥，索引共享。
- 32 个开发集配置：legacy/RRF × 向量 top-k {10,20,50,100} × 关键词 top-k {10,20,50,100}。
- RRF k=60，向量阈值 0.35、HNSW ef_search=80、记忆预算 450/750/1500 字节均不变。不补全查询、不增加 reranker、不移除既有 Python 匹配回退、不修改候选 SQL 的作用域过滤。
- 两组基准为 legacy 50/50、RRF 50/50；按 dev 指标为每种排序各选一个最优配置，去重后最多四组。先保存 selection_frozen.json，之后才执行新 holdout 检索和真实回答。

## 选择规则及上限

dev 阶段仅做真实检索，不调用回答模型。按有答案题“全部必要证据已注入”的题数、宏平均注入 recall、正样本注入 precision 依次排序；仍相同则优先两路候选总数更小、向量数量更小、词法数量更小的配置。禁止记忆命中非零的配置不能入选。

holdout 使用真实 `deepseek-flash` 回答，严格计分包括答案片段、必要引用和无答案拒答。每个问题轮换组执行顺序；不得用 holdout 重新挑选/调参。准入要求相对 legacy 50/50 严格正确题数增加、隔离违规为零，精确值/错误码/无答案正确题数不退化。

最多 208 次 DeepSeek 调用，每次输出上限 256 tokens；新增 embedding 调用上限 240。所有新向量调用统一 5 秒超时，仅实验生效。重复 query 在实验内共享同一真实向量，并在计时检索前预取，检索耗时不包括网络 embedding；网络延迟另列。

## 必须注意的解释边界

当前 selector 除索引候选外还扫描符合权限的记忆，用 Python 词面匹配补充候选。因此关键词 SQL top-k 不是最终词法候选总上限。trace 会记录两路配置值、索引实际候选数和 Python 补充候选数；缩小 top-k 不能直接解释为全链路工作量同比下降。

词法 SQL 仍在 top-k 后过滤 project/status/有效期；不合格候选可能先占位置。实验测的是现有实现的候选数量效果，不冒充完成作用域前置优化。

Recall@5 按预算筛选后的 selected_ids 计算；评测添加来源 ID 并重新按同一字节上限打包，另外报告实际 injected_ids。dev 证据命中不等于答案正确；最终回答通过率必须以 holdout 真实模型响应为准。

只有 272 条构造记忆，不能推断 1K/10K 或真实用户历史的通用最优参数。单题模板重复较多，服务实体才是重要泛化单位；不把大量配置/重复问法当成同等数量独立样本。

## 文件与入口

- `memories.json`：完整语料及作用域/状态。
- `cases.json`：全部问题、history、必要证据、禁止证据、标准答案片段及预算。
- `manifest.json`：运行前冻结的选择规则、参数和调用上限。
- `backend/scripts/prepare_memory_recall_v3.py`：确定性构造新数据，不覆盖已存在目录。
- `backend/scripts/memory_recall_eval_v3.py`：验证独立克隆库、扩充语料、dev 网格筛选、冻结入围组、真实 holdout。

生产默认保持 legacy、向量 50、关键词 50。本轮参数通过 provider 构造参数传入，仅供受控对照，不自动修改应用启动配置。
